## 程序相关 {#vault}

**程序库（Library）**
：审批策略的单位。决定这一批程序需要几人审批、能否自审自批、是否自动放行。

**程序（Program）**
：一个零件的一道工序的加工程序，由名称、零件号、工序、适用机型构成身份。

**版本（Version）**
：程序的一次具体内容。上传后**内容不可变**，只有状态会变。

**变体分组（Variant Group）**
：同一 `零件号 + 工序` 的多个程序（例如 FANUC 版和西门子版）在界面上归到一组，
但**从不合并**。

**来源（Origin）**
：这一版怎么来的——**上传** / **机边捕获** / **采纳**。

**内容哈希（Content Hash）**
：版本内容的 SHA-256。相同内容只存一份；排查问题时最硬的证据。

## 设备相关 {#fleet}

**网关（Gateway）**
：[彼络物联网关](https://docs.bivrost.cn/gateway/)。DNC Pro 通过它和机床对话，
自己从不直连机床。

**机台（Machine）**
：一台数控机床。台账由网关同步而来。

**机组（Machine Group）**
：授权和策略的单位（不是位置的单位）。决定谁能操作这些机床，以及允不允许试切。

**孤立机台（Orphaned）**
：曾同步过、但网关配置里已不存在的机床。保留历史，不再对它执行任何操作。

**严格模式（Strict Mode）**
：每台机床的开关。开启后在列表里**高亮标记未受管文件**。仅提示，**从不阻断**。

**最近校验（Last Verified）**
：这台机床最后一次被[滚动镜像](/guide/mirror/)**完整**扫完的时间。
失败的一轮不会更新它。

## 传输相关 {#transfer}

**机台分配（Assignment）**
：程序 ↔ 机床的绑定，规定机床上的文件名、目录和落地转换。

**落地转换（Transform）**
：发送前对内容做的处理：程序名改写、`%` 包裹、行结束符、目标编码。

**事务式下发（Transactional Transfer）**
：预检 → 快照 → 删除 → 发送 → 回读 → 校验的六阶段管线，
任一步失败自动回滚快照。

**回读（Readback）**
：把刚写进机床的内容读回来。**回读比对通过才算下发成功**。

**归一化比对（Normalized Comparison）**
：按厂商画像吸收无害差异（行结束符、O 号前导零、末尾空行）后再比对内容。

**回滚（Restore）**
：失败时用快照恢复机床上的原内容。结果分**无需回滚** / **已回滚** / **回滚失败**。

**批次（Batch）**
：一次操作产生的一组下发（同一版本发到多台机床）。每台独立成败。

**试制 / 试切（Trial / Prove-out）**
：限时的验证性下发，全程带徽标，到期后仍需人工**转正**或**撤回**。

## 镜像与漂移 {#mirror}

**滚动镜像（Rolling Mirror）**
：不停轮转整个机队、备份每台机床上每个文件的后台循环。永远给真实传输让路。

**快照（Snapshot）**
：某个机床文件在某一时刻的内容。来源分**下发前快照** / **回读快照** / **镜像快照**。

**受管文件 / 未受管文件（Managed / Unmanaged）**
：有[机台分配](/guide/assignments/)指向它的文件是受管的。
未受管文件同样被备份和保护，但**从不被检查或纠正**。

**采纳（Adopt）**
：把机床上的未受管文件收进程序库，以当前内容作为 v1。

**机边修改 / 漂移（Drift）**
：受管文件在机床侧被改动，被自动捕获成一个待处置的草稿版本。

**处置（Disposition）**
：对机边修改的决定——**采纳**（进入发布流程，机台不动）或
**拒绝**（可选推回受控版本）。

**推回（Push Back）**
：拒绝机边修改时，把已发布版本重新下发到机床。**必须显式勾选**。

## 权限与审计 {#rbac}

**角色（Role）**
：固定的五个：只读、操作工、编程员、审批员、管理员。

**范围（Scope）**
：授权的作用域：全局 / 机组 / 程序库。

**职责分离（Separation of Duties）**
：作者不能批准自己写的版本。默认开启。

**服务令牌（Service Token）**
：机器对机器集成用的凭据，形如 `dncp_<id>_<secret>`，走和人相同的 RBAC。

**代理身份（On-Behalf-Of）**
：令牌声明"这次操作实际由谁发起"，让审计能落到具体的人。

**内容外流（Content Egress）**
：任何一次程序正文的查看或下载。单独审计。

**哈希链（Hash Chain）**
：每条审计记录包含前一条的哈希。任何篡改都会让后续整条链对不上。

## 运维 {#ops}

**存活探针 `/healthz`**
：进程活着就返回 `ok`。用于重启策略。

**就绪探针 `/readyz`**
：断言 Postgres 可达、结构已迁移、blob 存储可写。用于监控告警。

**blob 存储（Blob Store）**
：按内容哈希寻址的程序内容存储（`/data/blobs` 卷）。
**它不可写时界面看起来一切正常，但上传和镜像全部静默失败。**
