## 6.4.1 适用范围 {#scope}

本节规定使用单位在日常使用中应执行的核查与维护工作。全部工作经管理控制台完成，
适用于系统管理员。

:::note[说明]
系统的安装、升级与服务器侧的运行维护由供应方负责，不属于本说明书的范围。
本节仅规定使用人员在界面上能够看到并处置的事项。
:::

## 6.4.2 日常状态查看 {#monitoring}

每个工作日应查看一次总览页。各项指标的含义与处理措施按表 6-10 的规定。

<p class="tbl-caption">表 6-10　总览页关注项</p>

| 关注项 | 含义 | 处理措施 |
| --- | --- | --- |
| 不可达网关 | 该网关当前无法访问，其下全部机台既不能下发也不能备份 | 检查网关供电与网络，见 [7.2.1](/faq/#sync-fails) |
| 镜像异常机台 | 该机台最近一轮备份失败 | 按行内显示的原因处理，见 [7.2.2](/faq/#mirror-fails) |
| 24 小时内失败的下发 | 存在下发未成功的机台 | 查看传输记录判定机床上的实际内容，见 [7.3.1](/faq/#after-failure) |
| 待审批版本、待处置机边修改 | 存在等待人工处置的事项 | 转交相应责任人处置 |

:::danger[警告]
不可达网关与镜像异常应在当班内处理。该状态持续期间，相关机床既无新的备份，
也不再进行机边修改检查，控制器数据丢失时将无近期快照可供还原。
:::

## 6.4.3 备份 {#backup}

本系统的备份分为两层，分工按下列规定：

a) 机床侧内容由滚动镜像持续备份，形成历史快照，使用单位无需另行操作，
   见 [5.6](/guide/mirror/)；

b) 本系统自身的数据（程序库、版本内容、审批与审计记录）由供应方在交付时配置定期备份。

:::danger[警告]
备份默认存放于本系统所在的服务器上。服务器整机故障时该备份同时失效。
使用单位应确认备份已同步至本系统主机之外的存储，并定期确认该同步仍在执行。
:::

系统自身数据的恢复由供应方或使用单位的 IT 部门执行，恢复完成后应逐台核对机台的
「最近校验」是否重新开始更新。

### 6.4.3.1 恢复被清空的机床 {#restore-machine}

机床控制器数据被清空且本系统数据完好时，操作步骤：

a) 进入「设备 → 机台 → 文件」，逐个文件执行「快照 → 还原」；

b) 受管文件亦可直接重新下发最新的已发布版本。

:::caution[注意]
还原经由与下发相同的事务式管线执行，执行前应确认机床未处于加工状态。
:::

还原规则见 [5.6](/guide/mirror/#restore)。

## 6.4.4 账号与凭据 {#security}

a) 首次登录后应立即修改交付时提供的管理员初始密码；

b) 管理员账号数量应尽量少，且不应用于日常操作。日常操作应使用编程员或审批员账号；

c) 集成应一律使用服务令牌，按最小范围授权并设定有效期，见 [5.9](/guide/admin/#tokens)；

d) 网关侧应为本系统建立专用账号与密钥，不应复用网关管理员账号，
   见 [4.1.2](/start/gateways/#gateway-account)；

e) 人员离职或转岗时应及时停用其账号，并吊销其名下的服务令牌。

## 6.4.5 定期核查 {#checklist}

每月执行一次，按表 6-11 逐项核查。

<p class="tbl-caption">表 6-11　月度核查项</p>

| 核查项 | 核查方法 | 合格判据 |
| --- | --- | --- |
| 网关状态 | 总览页 | 不可达网关数为 0 |
| 机台备份状态 | 设备页 | 镜像异常机台数为 0，全部机台的「最近校验」处于近期 |
| 审计链完整性 | 管理 → 审计 → 校验哈希链 | 结果为完整 |
| Webhook 投递 | 管理 → Webhook → 投递记录 | 无长期积压的失败投递 |
| 账号与令牌 | 管理 → 用户 | 离职人员账号已停用，无过期未清理的服务令牌 |
| 系统数据备份 | 向 IT 部门或供应方确认 | 近 30 天备份存在，且已同步至异地 |

核查中发现的异常应按第 [7 章](/faq/)的相应条款处置。
