## 7.0 适用范围 {#scope}

本章按功能分类给出常见故障现象、可能原因与处理措施，以及使用中的常见问题说明。
本章为处置性内容，各项措施的完整规则见其引用的条款。

## 7.1 访问与登录 {#access}

### 7.1.1 打不开管理控制台 {#cannot-open}

**处理措施。** 按下列顺序逐项排查：

a) 核对地址是否与实施人员提供的一致，包括端口号，见 [4.0.2](/start/#urls)；

b) 确认本机与本系统处于同一局域网内，办公网与车间网分隔时应使用车间网络；

c) 换用其他计算机或触摸屏访问，判断是本机问题还是系统问题；

d) 全部终端均无法访问时，应报请系统维护人员处理。

### 7.1.2 管理员密码丢失 {#admin-password}

**处理措施。**

a) 存在其他可用的管理员账号时，由该账号在「管理 → 用户」中重置密码，
   见 [5.9](/guide/admin/#users)；

b) 全部管理员账号均无法登录时，应报请系统维护人员处理，不应通过其他途径自行绕过登录。

:::caution[注意]
管理员账号不应仅设置一个。应至少保留两个管理员账号，避免单一账号失效导致无法管理系统。
:::

### 7.1.3 页面可打开，但程序上传总是失败 {#blob}

**原因。** 程序内容的存储不可写。

**处理措施。** 该故障在使用侧无法自行排除，应报请系统维护人员处理。

:::danger[警告]
程序内容存储不可写时，界面显示完全正常，但每一次上传与每一次镜像捕获都会静默失败。
故障期间不得以界面显示为准判断程序已保存，恢复后应重新上传并确认版本存在。
:::

## 7.2 网关与机台 {#gateway}

### 7.2.1 注册网关后同步不到机台 {#sync-fails}

**处理措施。** 按下列顺序逐项排查：

a) 确认本系统与该网关之间网络可达。排查时应以本系统所在的网络位置为准，
   操作人员个人电脑能打开网关页面并不说明本系统也能连通；

b) 确认网关地址填写为 `http://<IP>`，网关 HTTP 服务监听 80 端口，地址不应带路径；

c) 确认认证方式与密钥匹配。网关侧启用安全控制时必须填写密钥；

d) 确认网关侧的对应用户仍存在，且密钥未被重新生成。

网关注册方法见 [4.1.3](/start/gateways/#register)。

### 7.2.2 机台的「最近校验」持续不更新 {#mirror-fails}

**原因与处理措施。** 行内显示的失败信息与对应原因按表 7-1 的规定。

<p class="tbl-caption">表 7-1　镜像失败信息与原因</p>

| 行内显示 | 可能原因 | 处理措施 |
| --- | --- | --- |
| `Machine offline.` | 机床关机、网线松脱、网关侧该机台被停用 | 检查机床电源与网络，检查网关侧机台状态 |
| `No permission.` | 网关侧密钥失效或权限不足 | 按 [4.1.2](/start/gateways/#gateway-account) 重新生成密钥 |
| 持续显示「从未校验」 | 机台刚同步进入，尚未完成首轮扫描 | 等待数十秒至数分钟，时长取决于机队规模 |

:::note[说明]
「最近校验」仅在完整扫完一台机床后更新。该时刻不更新表示确实未完成备份，
不表示部分文件备份成功，见 [5.6](/guide/mirror/#pacing)。
:::

### 7.2.3 机床改名或增减后如何处理 {#resync}

重新执行一次「同步机台」。同步操作具备幂等性。网关配置中已不存在的机床被标记为孤立，
保留历史记录但不再被操作，见 [4.1.4](/start/gateways/#sync)。

## 7.3 程序下发 {#transfer}

### 7.3.1 下发失败后机床上的实际内容 {#after-failure}

**处理措施。** 查看传输记录中的两列，按表 7-2 判定。

<p class="tbl-caption">表 7-2　下发失败后的机床内容判定</p>

| 传输记录显示 | 机床上的内容 | 处理措施 |
| --- | --- | --- |
| 失败阶段为「预检」或「快照」 | 未被改动 | 排查网络与机床状态后重新下发 |
| 回滚结果为「已回滚」 | 为原有版本 | 生产可继续，排除故障后重新下发 |
| 回滚结果为「回滚失败」 | 不确定 | 应到机边人工核对后方可恢复生产 |

:::danger[警告]
回滚结果为「回滚失败」的文件处于内容未知状态，应在恢复生产前由具备机床操作资质的人员
到机边核对实际程序内容，见 [5.4](/guide/transfer/#restore)。
:::

### 7.3.2 发送至 FANUC 后程序号不正确 {#fanuc-number}

**原因。** FANUC 控制器忽略传入的文件名，程序名取自内容中的名称行。

**处理措施。** 在机台分配中将「程序名改写」设为目标 O 号，
见 [5.3](/guide/assignments/#fanuc) 与 [6.2](/reference/vendors/#fanuc-name)。

### 7.3.3 发送至西门子失败 {#siemens-ext}

**原因。** 西门子的 NC 文件必须带扩展名（`.MPF` 或 `.SPF`）。

**处理措施。** 检查机台文件名是否缺少扩展名，见 [6.2](/reference/vendors/#siemens)。

### 7.3.4 预检阶段即失败 {#preflight-fail}

**原因。** 预检校验机床可达性、程序号未被锁定、分配有效。程序号被锁定在 FANUC 与三菱上较常见，
厂商宏通常占用 O8000～O8999 等受保护区间。

**处理措施。** 更换目标程序号，见 [6.2](/reference/vendors/#lock-ranges)。

### 7.3.5 下发缓慢或排队时间过长 {#slow}

**原因与处理措施。**

a) 同一台机台同一时刻仅执行一个传输任务，批量下发至同一机台时串行执行，属正常行为；

b) 滚动镜像不会拖慢下发，它在每次网关调用前向传输让路，见 [5.4](/guide/transfer/#concurrency)；

c) 整体缓慢时，检查网关侧负载。网关同时承担数据采集任务且负载偏高时，
   可适当增大滚动镜像的节流间隔。

## 7.4 版本与审批 {#vault}

### 7.4.1 下发按钮不可用 {#cant-deploy}

**原因。** 仅「已发布」版本可执行下发。

**处理措施。** 按版本当前状态处理：

a) 草稿：执行提交审批；

b) 待审批：由审批人批准，票数不足时界面显示已获得的批准次数；

c) 废弃：不可下发。

版本状态规则见 [5.1](/guide/vault/#lifecycle)。

### 7.4.2 具备审批权限但无法批准本人创建的版本 {#self-approve}

**原因。** 该程序库启用了「禁止自审自批」，该项默认启用，属职责分离约束。

**处理措施。** 由他人审批；仅配备一名工程师的单位可停用该项，或将该程序库设为自动放行，
见 [5.2](/guide/approvals/#policy)。

### 7.4.3 机边捕获的版本为何是草稿 {#capture-draft}

捕获的版本已被安全保存，但尚不具备任何效力。在机边修改页面执行采纳后，
该版本才进入正常的审批发布流程，见 [5.7](/guide/drift/#disposition)。

## 7.5 机边修改 {#drift}

### 7.5.1 系统是否会自动还原机床上的改动 {#auto-revert}

不会。系统仅执行捕获、记录与排队，等待人工处置。
即使工程师选择「拒绝修改」，将已发布版本推回机床仍需单独勾选，
见 [5.7](/guide/drift/#reject-pushback)。

### 7.5.2 未受管文件被修改后没有记录 {#unmanaged-drift}

**原因。** 未受管文件被备份但不被检查，系统对其不存在「应当是什么」的基准。

**处理措施。** 需要对某个文件执行检查时，将其采纳进程序库，
见 [5.6](/guide/mirror/#adopt)。

### 7.5.3 试制期间调整参数是否产生大量记录 {#trial-drift}

不会。进行中的试制（含已过期未处置的试制）抑制该文件的机边修改捕获，
改动仍被完整备份，见 [5.5](/guide/trials/#drift-during-trial)。

### 7.5.4 同一文件被多次修改 {#repeat-drift}

后续改动更新同一条机边修改记录，不产生多条记录，
见 [5.7](/guide/drift/#capture)。

## 7.6 权限 {#rbac}

### 7.6.1 用户看不到部分机台或程序 {#scope}

**原因。** 授权范围（机组或程序库）限制了可见性。

**处理措施。** 在「管理 → 用户」中检查该用户的授权配置，见 [6.1](/reference/rbac/#scopes)。

### 7.6.2 403 与 409 的区别 {#403-409}

a) 403：当前角色或范围不覆盖目标对象，应检查授权；

b) 409：权限满足，但对象当前状态不允许该操作（例如下发草稿版本），应检查对象状态。

见 [6.1](/reference/rbac/#errors)。

### 7.6.3 操作工能否查看程序内容 {#operator-content}

不能。操作工不具备 `programs.content.view` 权限，可将正确的版本下发至机床，
但不能查看或下载程序正文，见 [5.8](/guide/shopfloor/#permissions)。

## 7.7 集成 {#integration}

### 7.7.1 Webhook 持续投递失败 {#webhook-fail}

**处理措施。** 在「管理 → Webhook → 投递记录」中查看 HTTP 响应码与错误信息。
常见原因包括：接收端地址无法解析、防火墙拦截、接收端返回非 2xx 响应。
排除故障后执行「重新投递」，见 [5.9](/guide/admin/#webhooks)。

### 7.7.2 API 调用提示 CSRF 相关错误 {#csrf}

**原因。** 使用 Cookie 会话的非 GET 请求必须携带 `X-Requested-With: XMLHttpRequest` 请求头。

**处理措施。** 机器对机器的集成不应使用 Cookie 会话，应改用服务令牌的
`Authorization: Bearer dncp_...`，该方式不受此约束，见 [6.3](/reference/api/#auth)。

### 7.7.3 服务令牌丢失后能否找回 {#token-lost}

不能。令牌明文仅在创建时显示一次，系统仅存储其哈希值。
应吊销原令牌并新建，见 [5.9](/guide/admin/#tokens)。

## 7.8 其他 {#misc}

### 7.8.1 能否完全断网运行 {#offline}

可以。使用本地账号时，整套系统运行于使用单位的局域网内，全部数据存储于使用单位自有服务器，
不需要任何外网连接。OIDC 单点登录为可选项，不启用即可。

### 7.8.2 界面是否提供英文版 {#i18n}

提供。管理控制台与机边操作台的右上角均可在简体中文与 English 之间切换。

### 7.8.3 一套系统可管理几个车间 {#multi-shop}

每个车间部署一台彼络物联网关，本系统侧注册多条网关记录即可，
网关注册方法见 [4.1.3](/start/gateways/#register)。
