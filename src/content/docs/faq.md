## 部署 {#deploy}

### 装完了，页面能开，但传程序总失败 {#blob}

先看 `/readyz`：

```bash
curl -fsS http://<主机>:8030/readyz | jq
```

十有八九是 `blob-store` 这一项 `fail`。blob 存储不可写时，
**界面完全正常，但每一次上传和每一次镜像捕获都静默失败**。
常见于换卷、改挂载权限之后。

### 首启的管理员密码找不到了 {#admin-password}

密码只在首次启动时打印一次。如果没记下来：

```bash
docker compose logs api | grep "admin"
```

日志还在的话能翻出来。翻不出来的话，在 `.env` 里设
`DNCPRO__Bootstrap__AdminPassword=...`，然后**清空 users 表**让引导重跑——
这会连带清掉所有用户，仅适用于还没投入使用的新装环境。
已投产环境请找另一个管理员账号重置。

### 能装在 Windows 上吗 {#windows}

不能作为生产部署目标。DNC Pro 只支持 Linux 主机上的 Docker Engine。
Windows Server、WSL2、Docker Desktop 均不在支持范围内。

## 网关与机台 {#gateway}

### 注册网关后同步不到机台 {#sync-fails}

按这个顺序查：

1. 从 **DNC Pro 主机**（不是你的笔记本）`curl http://<网关IP>/` 能通吗
2. 网关地址填的是 `http://<IP>` 吗（网关 HTTP 在 80 端口，不要带路径）
3. 认证方式和密钥对得上吗——网关侧安全控制启用时必须填密钥
4. 网关侧那个用户还在、密钥没被重新生成过吗

### 某台机床的"最近校验"一直不更新 {#mirror-fails}

行内会显示具体原因。常见的几种：

| 显示 | 原因 |
| --- | --- |
| `Machine offline.` | 机床关机、网线松、网关侧该机台被停用 |
| `No permission.` | 网关侧密钥失效或权限不足 |
| 一直"从未校验" | 机台刚同步进来，等一轮扫描（几十秒到几分钟，取决于机队规模） |

注意：只有**完整扫完**一台机床才会更新"最近校验"。
所以这个时间不更新意味着真的没备份成功，不是"部分成功"。

### 机床改名 / 增减了怎么办 {#resync}

重跑一次**同步机台**即可，同步是幂等的。
消失的机床会被标记为**孤立**，保留历史但不再被操作。

## 下发 {#transfer-fails}

### 下发失败了，机床上现在是什么 {#after-failure}

看传输记录里的两列：

- **失败阶段**是"预检"或"快照" → 机床**没被碰过**
- **回滚**是"已回滚" → 机床上是原来那版，生产可以继续
- **回滚**是"回滚失败" → **需要有人去机床边确认**，这是唯一的例外

### 发到 FANUC 上程序号不对 {#fanuc-number}

FANUC **忽略传入的文件名**，程序名取自内容里的名字行。
在[机台分配](/guide/assignments/)里把"程序名改写"设为目标 O 号即可。

这是 FANUC 相关问题里最常见的一个，详见[机床系统差异](/reference/vendors/#fanuc-name)。

### 发到西门子上失败 {#siemens-ext}

西门子的 NC 文件**必须带扩展名**（`.MPF` / `.SPF`）。
检查机台文件名是不是漏了扩展名。

### 预检阶段就失败了 {#preflight-fail}

预检检查机床可达、程序号未被锁定、分配有效。
"程序号被锁定"在 FANUC 和三菱上很常见——
厂商宏通常占用 O8000–O8999 之类的受保护区间。换一个号即可。

### 下发很慢 / 排队很久 {#slow}

同一台机床同一时刻只跑一个传输任务，批量下发到同一台机床会串行。
[滚动镜像](/guide/mirror/)不会拖慢下发——它每次网关调用前都给传输让路。

如果整体都慢，看网关侧的负载，以及 `DncPro__Mirror__InterRequestDelayMs`
是不是设得太激进。

## 版本与审批 {#vault}

### 为什么下发按钮是灰的 {#cant-deploy}

只有**已发布**版本能下发。检查版本状态：

- **草稿** → 需要提交审批
- **待审批** → 需要审批人批准（可能还差人，看"已获 N 次批准"）
- **废弃** → 不能下发

### 我有审批权限，但批不了自己写的版本 {#self-approve}

程序库开启了"禁止自审自批"（**默认开启**）。这是[职责分离](/reference/rbac/)。

一个人的车间可以关掉它，或者把这个库设成**自动放行**。

### 机边捕获的版本为什么是草稿 {#capture-draft}

因为它只是被**安全保存**下来了，还没有任何效力。
在[机边修改](/guide/drift/)页面**采纳**后，它才进入正常的审批发布流程。

## 机边修改 {#drift}

### 操作工改了程序，系统会自动改回去吗 {#auto-revert}

**不会。** 系统只会捕获、记录、排队等人处置。

即使工程师选择"拒绝修改"，"把已发布版本推回机床"也是一个需要**单独勾选**的动作。

### 未受管文件被改了，为什么没有记录 {#unmanaged-drift}

未受管文件**被备份但从不被检查**——它们没有"应该是什么"的基准。
如果你希望某个文件被检查，把它[采纳](/guide/mirror/#adopt)进程序库。

### 试切期间改参数会刷屏吗 {#trial-drift}

不会。进行中（含已过期未处置）的[试制](/guide/trials/)会抑制该文件的漂移捕获。
改动仍然被完整备份。

### 同一个文件被改了好几次 {#repeat-drift}

后续改动**更新同一条记录**，不会产生多条。队列不会因为一个人反复调参而爆掉。

## 权限 {#rbac}

### 用户看不到某些机台 / 程序 {#scope}

授权范围（机组 / 程序库）限制了可见性。在**管理 → 用户**里检查这个人的授权。

### 403 和 409 有什么区别 {#403-409}

- **403**：你的角色或范围覆盖不到目标——查授权
- **409**：权限没问题，但对象当前状态不允许（例如下发草稿）——查状态

### 操作工能看到程序内容吗 {#operator-content}

**不能。** 操作工没有 `programs.content.view`。
他能把正确的版本发到机床上，但不能查看或下载程序正文。

## 集成 {#integration}

### Webhook 一直投递失败 {#webhook-fail}

**管理 → Webhook → 投递记录**里有具体的 HTTP 响应码和错误信息。
常见原因：接收端地址在 DNC Pro 容器里解析不了、防火墙、接收端返回非 2xx。

修好之后可以点**重新投递**。

### 用 API 调用时提示 CSRF 相关错误 {#csrf}

用 Cookie 会话的**非 GET** 请求必须带 `X-Requested-With: XMLHttpRequest` 头。

机器对机器的集成不要用 Cookie，改用[服务令牌](/guide/admin/#tokens)的
`Authorization: Bearer dncp_...`，不受这个限制。

### 令牌丢了能找回来吗 {#token-lost}

不能。令牌**只在创建时显示一次**，系统只存哈希。
丢了就吊销旧的、新建一个。

## 其他 {#misc}

### 可以完全断网运行吗 {#offline}

可以。本地账号 + 本地 Postgres + 本地文件存储，
整套系统跑在你的局域网里，不需要任何外网连接。

OIDC 单点登录是可选的，不启用即可。

### 界面有英文版吗 {#i18n}

有。控制台和机边操作台右上角都可以切换简体中文 / English。

### 一台 DNC Pro 能管几个车间 {#multi-shop}

每个车间一台彼络网关，DNC Pro 侧注册多条网关记录即可。
机队规模建议见[运维手册 · 容量](/reference/operations/#capacity)。
