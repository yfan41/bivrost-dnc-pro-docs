## 三层结构 {#structure}

```text
程序库（审批策略的单位）
  └── 程序（零件号 + 工序，人看的身份）
        └── 版本（不可变内容 + 线性版本号）
```

- **程序库**决定这一批程序需要几个人批、能不能自审自批、要不要自动放行。
- **程序**是身份：名称、零件号、工序、适用机型、说明。
- **版本**是内容：上传之后**内容永不可改**，能变的只有它的状态。

![程序库](/img/console/vault.png)

<p class="shot-caption">按程序库筛选、按名称/零件号/工序搜索；「已发布版本」列直接告诉你现在下发会发出哪一版</p>

## 版本的生命周期 {#lifecycle}

```text
   上传 ────► 草稿 ──提交审批──► 待审批 ──批准──► 已发布
                ▲                  │                │
                └──────驳回────────┘             废弃│
                                                     ▼
                                                   废弃
```

| 状态 | 能做什么 |
| --- | --- |
| **草稿** | 可以提交审批、可以废弃。**不能下发** |
| **待审批** | 等审批人决定。作者可以看，不能自己改成已发布 |
| **已发布** | 可以下发到机台。同一程序可以有多个已发布版本，下发时选具体某一版 |
| **废弃** | 不再出现在可下发列表中，历史保留 |

程序整体也可以**废弃**：整个程序退役时用，废弃后默认不在列表里显示。

## 版本的三种来源 {#origins}

版本行上的**来源**标签说明这一版是怎么来的，这是追溯时的关键信息：

| 来源 | 含义 |
| --- | --- |
| **上传** | 人从 CAM 或编辑器上传的 |
| **机边捕获** | [滚动镜像](/guide/mirror/)在机床上发现受管文件被改动，自动捕获回来的 |
| **采纳** | 机床上原本未受管的文件被[采纳](/guide/mirror/#adopt)进程序库时的基线 |

![程序详情](/img/console/program-detail.png)

<p class="shot-caption">v1/v2 是上传的已发布版本，v3 是待审批，v4/v5 是从两台机床上捕获回来的机边修改</p>

机边捕获的版本进来时是**草稿**——它已经被安全保存下来，但还没有任何效力，
等工程师在[机边修改](/guide/drift/)页面处置。

## 内容去重 {#dedup}

版本内容按 SHA-256 寻址存储。两个版本内容完全一致时，底层只存一份。
这带来一个实际好处：**滚动镜像每天为几十台机床拍的快照，绝大多数是重复内容，
几乎不占额外空间**。

版本详情里的**内容哈希**是排查问题时最硬的证据——
下发记录里的"转换后哈希"和"回读哈希"都可以和它对照。

## 并排比对 {#diff}

版本表最右侧的**对比**勾选框：勾任意两版，界面给出并排差异。
审批时的评审弹窗默认展示的就是"与上一版的差异"。

![差异比对](/img/console/approval-review.png)

差异按行计算，删除行标红、新增行标绿。对 G 代码来说这基本等同于"改了哪几刀"。

## 变体分组 {#variants}

同一个零件号 + 同一道工序，可能因为机床不同而存在多个程序
（例如 FANUC 版和西门子版）。DNC Pro 用 `零件号::工序` 作为**变体分组键**，
在界面上把它们归到一起，但**从不合并**——它们仍是各自独立的程序，
各有各的版本历史和审批记录。

## 下载与内容外流 {#egress}

版本行的**下载**按钮取出该版本的原始内容。
每一次查看正文或下载都会写一条 `version.view` 审计记录，记录谁、什么时候、
从哪个 IP 取走了哪一版的内容。

:::note
这不是限制，是记录。追溯时"这份程序都流出去给过谁"是一个必须能回答的问题。
:::

## 权限 {#permissions}

| 动作 | 需要 |
| --- | --- |
| 看到程序列表与元数据 | `programs.read`（编程员/审批员/只读/管理员） |
| 看正文、下载 | `programs.content.view`（编程员/审批员/管理员） |
| 只看已发布版本 | `programs.read.released`（操作工也有） |
| 新建程序、上传版本、废弃 | `programs.write`（编程员/管理员） |
| 提交审批 | `versions.submit`（编程员/管理员） |

权限可以按**程序库**授予——例如试制组工程师只在试制程序库里有编程员权限。
详见[角色与权限](/reference/rbac/)。
