## 分配是什么 {#what}

一条**机台分配**回答三个问题：

> 这个程序发到那台机床上时，叫**什么名字**、放在**哪个目录**、内容要做**什么转换**。

一个程序可以有多条分配（同一程序铺到多台机床），
一台机床上也可以有多条分配（多个程序）。

![机台分配](/img/console/program-detail.png)

<p class="shot-caption">泵体粗铣分配到三台加工中心，都落地为 O1001，转换规则一致</p>

## 四项转换 {#transforms}

| 转换 | 值 | 什么时候用 |
| --- | --- | --- |
| **程序名改写** | 目标程序名，如 `O1001` | **FANUC 必用**；其他系统按需 |
| **保证 `%` 包裹** | 开 / 关 | 内容首尾自动补 `%` 行 |
| **行结束符** | `LF` / `CRLF` | 机床对换行敏感时 |
| **目标编码** | 编码名 | 程序里有非 ASCII 注释时 |

转换在**发送前**对内容执行，机床上落地的是转换后的字节。
下发记录里的**转换后哈希**就是这些字节的 SHA-256。

## FANUC：程序名来自内容 {#fanuc}

这是最容易踩的一个坑，值得单独讲。

FANUC 控制器在接收文件时**忽略传入的文件名参数**。
它从内容里取名——具体是**第一个换行符和第二个换行符之间的那一行**：

```text
%                         ← 第一行
O1001(PUMP BODY ROUGH)    ← 控制器从这一行取名：O1001
G17 G21 G40 G49 G80 G90
...
```

也支持尖括号形式：`<PUMPROUGH>`。

**后果**：如果你把一个内容里写着 `O5` 的程序，分配到机台文件名 `O1001`，
但没有设置"程序名改写"，那么它在机床上会变成 **O5**，而不是 O1001。
下一次下发别的程序到 O1001 时，你会发现"目标是空的"。

所以：**给 FANUC 机床做分配时，把"程序名改写"设成和机台文件名相同的 O 号。**

还有一层：FANUC 在列目录时会把标准 O 号的前导零去掉
（`O0010` 显示成 `O10`），不同代次的控制器行为还不一样。
DNC Pro 在比对时会归一化这些写法，你不需要关心——但知道这件事有助于理解
为什么机床屏幕上的名字和你填的不完全一样。

更多厂商差异见[机床系统差异](/reference/vendors/)。

## 目录 {#dir}

**机台目录**留空时使用这台机床的文件根目录（由网关的机床配置提供，
例如 FANUC 是 `//CNC_MEM/`、西门子是 `/nckfs`、三菱是 `PRG\USER\`）。

不是所有系统都支持指定目录。不支持的系统上，填了也会落到根目录——
这是控制器的限制，不是配置错误。

## 预览转换 {#preview}

分配建好后可以对某个版本做**预览转换**，得到：

- 转换后的完整文本（就是会写到机床上的那些字节）
- 它的 SHA-256
- 字节数

**这个哈希应当与实际下发记录里的"转换后哈希"完全一致。**
如果不一致，说明分配在两次之间被改过。

预览是排查"发过去怎么不对"的第一站——先确认发出去的内容对不对，
再去怀疑机床。

## 一个程序，多台机床 {#fan-out}

批量下发时可以一次勾选多条分配，系统生成一个**批次**，
每台机床一条独立的下发记录，各自独立成功或失败。

一台失败不会回滚其他台——每台机床的事务是独立的。
批次只是一个便于查询的分组。

## 文件名归一化 {#normalize}

分配保存时会记录一个**归一化文件名**，用于和机床上列出来的名字做匹配。
FANUC 的 O 号零填充差异在这一层被吸收，所以：

- 机床上叫 `O0001`、你填 `O1`——匹配得上
- 机床上叫 `PART.NC`、你填 `part.nc`——**匹配不上**（非 FANUC 系统区分大小写）

## 权限 {#permissions}

建立和修改分配需要 `programs.write`（编程员 / 管理员）。
授权范围可以按程序库限定。
