## 它是给谁用的 {#audience}

机边操作台跑在车间工位的触摸屏或平板上，给**操作工**用。

设计目标只有三条：

1. **只显示他有权限的机台**——不需要在 50 台机器里找自己那 6 台
2. **只显示这台机床该跑的程序**——不需要在程序库里搜零件号
3. **一眼看出机床上是不是最新版**——不需要问工艺

地址：`http://<主机>:8030/shopfloor/`

## 登录 {#login}

![机边登录](/img/shopfloor/login.png)

用操作工自己的账号。触摸屏建议在浏览器里设成主页或加到桌面。

## 我的机台 {#machines}

![我的机台](/img/shopfloor/machines.png)

<p class="shot-caption">这位班组长的授权范围是「加工中心组」，所以只看到这 6 台</p>

每张卡片给出：机床名、系统型号、**最近检查**时间、程序数量。
镜像异常的机床会显示**备份异常**标记。

## 机台页面 {#machine}

![机台页面](/img/shopfloor/machine.png)

<p class="shot-caption">绿色边条 = 一致，可以开工；红色 = 这个程序在机床上被改过，等工艺处置</p>

每个程序一张卡片，包含：

- 程序名、零件号 + 工序、**机床上的文件名**
- 当前受控版本号
- **发送到机床**按钮（点击后需再确认一次）

状态行只有五种，都是给操作工看的大白话：

| 状态 | 含义 | 该做什么 |
| --- | --- | --- |
| **机床上已是最新版本** | 一致 | 直接开工 |
| **机床上不是最新版本** | 机床上是旧版 | 点"发送到机床" |
| **尚未发送到此机床** | 这台机床上还没有 | 点"发送到机床" |
| **机床上的程序被改过，等待编程员处理** | 有一条待处置的[机边修改](/guide/drift/) | 先问工艺，别自己覆盖 |
| **无已发布版本** | 这个程序还没有可用的已发布版本 | 找工艺 |

页面顶部另有两条整机提示：**最近检查**时间，以及
"**N 个文件状态异常，请联系编程员**"（[回滚失败](/guide/transfer/#restore)之类的情况）。

点"发送到机床"执行一次标准的[事务式下发](/guide/transfer/)——
操作工按的按钮和工艺在控制台上按的是同一条管线，同样有快照、回读和校验。

## 我改了程序，立即检查 {#check-now}

页面顶部的这个按钮让这台机床**插队**到[滚动镜像](/guide/mirror/)队列最前面。

这是给操作工的诚实通道：改完主动说一声，改动会在几秒内被捕获成
[机边修改](/guide/drift/)记录，进入工程师的处置队列——
而不是等下一轮扫描，或者等下次下发时被覆盖掉。

:::tip[值得在班前会上讲一遍]
"你在机床上调的参数，点这个按钮，工艺那边就能看到并且可能采纳成正式版本。"
比"不许改程序"有用得多。
:::

## 操作工能做什么、不能做什么 {#permissions}

| 能 | 不能 |
| --- | --- |
| 看到授权机组内的机台 | 看到其他机组的机台 |
| 看到**已发布**版本 | 看到草稿和待审批版本 |
| 下发已发布版本 | 下发[试制](/guide/trials/)版本 |
| 请求立即检查 | 处置[机边修改](/guide/drift/) |
| | 查看/下载程序正文 |

操作工角色**没有** `programs.content.view`——
他能把正确的程序发到机床上，但不能把程序内容取走。

## 中英文切换 {#i18n}

右上角可以在简体中文和 English 之间切换，选择记在这台设备上。
外籍或跨厂调机人员不需要额外配置。

## 部署建议 {#deployment}

- 触摸屏用 Chrome/Edge 全屏模式（kiosk mode），主页设为 `/shopfloor/`
- 一台屏可以给整个班组共用，但建议**每人自己的账号**——审计要落到人
- 屏幕分辨率 1280×800 以上体验最好，界面本身是自适应的
