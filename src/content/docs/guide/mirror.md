## 它在做什么 {#what}

滚动镜像是一个**永不停止的循环**：轮转整个机队，一台一台把机床上的
**每一个文件**读回来，存成按内容寻址的快照。

它备份的不只是受管程序——**机床上所有文件**都在保护范围内，
包括历年积累的、从没进过任何文件夹的机床本地程序。

## 节奏与礼貌 {#pacing}

镜像的设计前提是"它必须永远排在生产后面"：

| 规则 | 说明 |
| --- | --- |
| 每台网关同一时刻只扫**一台**机床 | 不给网关制造并发压力 |
| 请求之间有节流间隔 | 默认 250ms |
| 空闲一轮后休眠 | 默认 5s，然后重新开始 |
| **给真实传输让路** | 每一次网关调用之前都检查有没有待执行的传输任务 |
| **跳过当前运行的程序** | 不去打扰正在加工的那个文件 |
| 只有**完整扫完**才更新"最近校验" | 失败的一轮绝不冒充成功的备份 |

最后一条很重要：如果一台机床的"最近校验"停在两小时前，
那就是真的两小时没成功备份过，而不是"扫了但有几个文件失败"。

## 最近校验与镜像异常 {#health}

![设备页](/img/console/fleet.png)

<p class="shot-caption">卧加01 的备份失败原因就写在行内，不需要去翻服务器日志</p>

镜像失败被**记录在这台机床上**，在设备页、机台详情页和机边操作台上都能看到，
总览页的"镜像异常机台"给出计数。

:::tip[这是刻意的产品决定]
备份失败如果只写进日志，实际效果等于没有备份——没人会去看日志。
所以 DNC Pro 把它摆到控制台上。
:::

## 立即检查 {#check-now}

机台详情页右上角的**立即检查**让这台机床**插队**到镜像队列最前面。
操作工在机边操作台上也有一个对应的大按钮——**我改了程序，立即检查**。

![机边操作台](/img/shopfloor/machine.png)

这是给操作工的一个诚实通道：改完了主动说一声，比等系统轮到它快得多。

## 快照与还原 {#restore}

每个文件的每一代内容都存成快照，来源分三种：

| 来源 | 什么时候产生 |
| --- | --- |
| **下发前快照** | [事务式下发](/guide/transfer/)第 ② 步 |
| **回读快照** | 下发校验通过后，把回读到的内容存下来 |
| **镜像快照** | 滚动镜像发现内容变了 |

在机台详情页的文件行点**快照**，可以看到这个文件的历史，
并把任意一代**还原**回机床。还原走的是和下发同样的事务式管线
（快照 → 删除 → 发送 → 回读 → 校验）。

机床控制器被清空时的恢复流程：

1. 从备份恢复 DNC Pro（数据库 + blob 存储），如果 DNC Pro 本身还在则跳过
2. 机台详情页 → 逐个文件 → 快照 → 还原
3. 受管文件也可以直接重新[下发](/guide/transfer/)最新的已发布版本

## 未受管文件 {#unmanaged}

机床上不属于任何[机台分配](/guide/assignments/)的文件叫**未受管**。

![机台文件](/img/console/machine-detail.png)

未受管文件：

- <span class="sup-y">✓</span> **被完整备份**，有历史快照，可以还原
- <span class="sup-n">✗</span> **从不被"纠正"**——它们改了不产生[机边修改](/guide/drift/)记录，
  不会有人被叫去处置

这是刻意的：车间里总有一堆对刀宏、暖机程序、临时工装程序，
它们不需要走审批流程，但绝不能丢。

**严格模式**（每台机床的开关）会把未受管文件在列表里**高亮标出**，
仅提示，从不阻断。适合"这台机床上不该有计划外程序"的场合。

## 采纳 {#adopt}

未受管文件可以一键**采纳**进某个程序库：

- 单个文件：文件行的**采纳**按钮
- 整台机床：右上角选择目标程序库后点**全部采纳**

采纳会：

1. 在目标程序库里建一个程序（可指定名称、零件号、工序）
2. 以机床上的当前内容作为 v1，来源标记为**采纳**
3. 自动建立一条指向这台机床、这个文件名的[分配](/guide/assignments/)

采纳之后这个文件就进入受控世界：有版本、有审批、有漂移检测。

:::caution
采纳的 v1 是"机床上现在是什么就是什么"，它不一定是对的。
建议采纳后先人工审阅一遍，再决定是否作为基线发布。
:::

## 存储成本 {#storage}

快照按内容哈希去重。绝大多数镜像扫描发现的是"内容没变"，
不产生新的存储。真正占空间的只有实际发生的每一次变更。

一个 30 台机床、每台 40 个程序的车间，程序内容总量通常在几十 MB 量级——
快照历史再多也远小于一张图纸的扫描件。

## 关闭镜像 {#disable}

镜像默认开启。极少数场景（例如网关侧资源极度紧张）可以关掉：
在 `worker` 的环境变量里设 `DncPro__Mirror__Enabled=false`。

:::danger
关掉镜像意味着**放弃全部备份能力和机边修改检测**。
下发依然工作，但"机床上现在是不是那一版"这个问题将无法回答。
:::
