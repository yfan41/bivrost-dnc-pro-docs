这一章带你从一台空的 Linux 主机走到"第一个程序成功下发到机床并通过回读校验"。
全程大约 30 分钟，其中大部分时间在等 docker 构建镜像。

| 步骤 | 做什么 | 需要谁 |
| --- | --- | --- |
| [4.1 安装部署](/start/install/) | 起 compose 栈、拿到首个管理员密码、确认 `/readyz` 就绪 | 有主机 root 的 IT |
| [4.2 接入网关与机台](/start/gateways/) | 在网关侧建账号、在 DNC Pro 注册网关、同步机台、分机组 | 设备管理 |
| [4.3 第一次下发](/start/first-transfer/) | 建程序库 → 建程序 → 上传版本 → 审批放行 → 绑定机台 → 下发 | 工艺工程师 |

## 先决条件核对 {#preflight}

开始之前确认这几件事，能省掉大半的排查时间：

- [ ] Linux x86-64 主机，Docker Engine ≥ 24、compose v2
- [ ] 从这台主机 `curl http://<网关IP>/` 能通（网关 HTTP 在 80 端口）
- [ ] 网关侧已经有一个可用的登录账号，且知道怎么进"设置 → 用户管理"
- [ ] 主机有固定 IP 或 DNS 名，车间的浏览器/触摸屏能访问到 `8030` 端口

## 关于手册里的演示环境 {#demo-env}

本手册的截图来自一套可复现的演示数据集：

- 两台车间网关（`一号车间网关` / `二号车间网关`），后者启用了密钥认证
- 10 台机床，覆盖 FANUC 31i / 0i-F / 0i-D、SIEMENS 828D / 840D sl、
  Mitsubishi M80、Brother S700X1 / TC-S2D 七种系统组合
- 三个程序库，分别用三套不同的审批策略（单人审批、自动放行、双人会签）
- 六名不同角色、不同授权范围的人员
- 一批真实跑通的下发（含一次失败并自动回滚）、两个进行中的试切、四条待处置机边修改

演示环境用的是 DNC Pro 自带的 **Fake Gateway**（协议的独立再实现，测试资产之一）
充当网关，因此不需要真机就能完整演练所有流程。
它监听 `/_fake/*` 控制面，可以精确编排机床、文件、故障注入等场景。

:::caution[演示数据不要用在生产上]
演示数据集里的账号密码是公开的示例值。真实部署请按 [4.1](/start/install/) 的说明
用首启生成的随机密码登录并立即修改。
:::
