## 4.1.1 适用范围 {#scope}

本节规定彼络物联网关的接入方法与机台台账的建立方法。适用于设备管理人员与管理员。

本系统经由网关与机床通信，不直接连接机床。

## 4.1.2 建立网关专用账号 {#gateway-account}

:::caution[注意]
不应使用网关的管理员账号供本系统直连。管理员账号的口令变更会影响其他用途，
且操作责任无法区分。
:::

操作步骤：

a) 打开网关界面，进入「设置 → 用户管理」，新建一个专供本系统使用的用户；

b) 在该用户的「用户安全」中生成 Secret Key；

c) 保持网关的安全控制处于启用状态。

详细步骤见[网关说明书 · 设置](https://docs.bivrost.cn/gateway/usage/settings/)。

## 4.1.3 注册网关 {#register}

操作步骤：进入「设备 → 注册网关」，按表 4-3 的规定填写各字段并保存。

<p class="tbl-caption">表 4-3　网关注册字段</p>

| 字段 | 填写要求 |
| --- | --- |
| 名称 | 车间内通用的称谓，例如 `一号车间网关` |
| 网关地址 | `http://<网关IP>`，网关 HTTP 服务监听 80 端口 |
| 认证方式 | `密钥`（推荐，填入 4.1.2 生成的 Secret Key）、`用户名密码`，或 `无`（仅限完全隔离的可信网段） |

![设备页](/img/console/fleet.png)

<p class="shot-caption">图 4-2　设备页面的网关列表</p>

图 4-2 中共注册两台网关，一台位于可信网段采用无认证方式，另一台采用密钥认证。

:::note[说明]
网关行的「最近可达」记录最近一次成功同步的时刻，不是心跳时刻。
判定机床当前是否处于正常备份状态应查看机台行的「最近校验」，
该值由滚动镜像持续更新，见 [5.6](/guide/mirror/)。
:::

:::caution[注意]
网关凭据以加密形式存储，不在任何界面或 API 响应中回显。
更换密钥时应重新注册一台网关，原网关停用。
:::

## 4.1.4 同步机台台账 {#sync}

操作步骤：在目标网关行单击「同步机台」。

系统读取网关的机床配置并更新台账，处理规则如下：

a) **新增**：网关上存在、本系统中不存在的机床；

b) **更新**：名称、控制系统、型号、IP、编码、文件根目录等属性发生变化的机床；

c) **孤立**：曾同步过、但本次网关配置中不存在的机床。系统保留其历史记录，
   不再对其执行任何操作。

同步操作具备幂等性，可随时重复执行。机床增减或改名后应重新执行一次同步。

## 4.1.5 划分机组 {#groups}

机组是授权与策略的施加单位，不表示物理位置。机组决定下列两项：

a) 可操作该组机床的人员范围。权限可按机组授予，见 [6.1](/reference/rbac/)；

b) 该组机床是否允许试制。该项为机组级开关，见 [5.5](/guide/trials/#group-policy)。

演示环境的机组划分按表 4-4 的规定。

<p class="tbl-caption">表 4-4　演示环境的机组划分</p>

| 机组 | 所含机台 | 允许试制 |
| --- | --- | :---: |
| 加工中心组 | 立加 01/02、卧加 01、高速铣 01、五轴 01、精雕 01 | <span class="sup-y">✓</span> |
| 车削组 | 数车 01、车铣复合 01 | <span class="sup-y">✓</span> |
| 钻攻中心组 | 钻攻 01、钻攻 02 | <span class="sup-n">✗</span> |

钻攻中心为量产节拍机，不允许出现试制程序。该策略由机组开关强制执行，不依赖人员记忆。

## 4.1.6 机台级选项 {#machine-options}

在设备页的机台表中按行设置，选项按表 4-5 的规定。

<p class="tbl-caption">表 4-5　机台级选项</p>

| 选项 | 含义 |
| --- | --- |
| 机组 | 该机台归属的机组，决定授权范围与试制策略 |
| 严格模式 | 在该机台的文件列表中高亮标记未受管文件。仅作提示，不阻断任何操作 |

严格模式适用于不允许出现计划外程序的机台，其作用是标出待核查项，不是阻断操作。

## 4.1.7 接入结果验证 {#verify}

同步完成后不执行任何其他操作，等待 1～2 分钟后返回设备页，按下列各项核对：

a) 每台机床的「最近校验」应由空白变为「刚刚」，表明滚动镜像已完成一轮扫描；

b) 进入任一机台详情页，应能看到该机床上已有的文件，且全部标记为「未受管」。

![机台文件](/img/console/machine-detail.png)

<p class="shot-caption">图 4-3　接入后的机台文件列表</p>

图 4-3 中，机床上原有的文件均为未受管状态：已被备份，但不受任何策略约束。
纳入受控管理的方法见 [5.6](/guide/mirror/#adopt)。

某机台的「最近校验」持续不更新时，行内显示具体失败原因（例如 `备份失败: Machine offline.`）。
常见原因与处理措施见 [7.2](/faq/#gateway)。

接入完成后按 [4.2](/start/first-transfer/) 执行首次程序下发。
