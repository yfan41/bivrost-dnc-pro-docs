---
title: "4.2. 接入网关与机台"
description: 在网关侧建密钥、在 DNC Pro 注册网关、同步机台台账、划分机组
---

DNC Pro 通过彼络网关和机床对话。这一步把网关接进来，并让机台台账自动填好。

## 第一步：在网关侧准备一个专用账号 {#gateway-account}

不要用网关的管理员账号直连 DNC Pro——出了问题不好追责，改密码也会连带影响。

1. 打开网关界面 → **设置 → 用户管理**，新建一个专用于 DNC Pro 的用户
2. 在该用户的**用户安全**里生成一个 **Secret Key**
3. **保持网关的安全控制处于启用状态**

详细步骤见[网关说明书 · 设置](https://docs.bivrost.cn/gateway/usage/settings/)。

## 第二步：在 DNC Pro 注册网关 {#register}

**设备 → 注册网关**，填三项：

| 字段 | 说明 |
| --- | --- |
| 名称 | 车间里叫得出口的名字，例如 `一号车间网关` |
| 网关地址 | `http://<网关IP>`（网关 HTTP 在 80 端口） |
| 认证方式 | `密钥`（推荐，填上一步生成的 Secret Key）、`用户名密码`，或 `无`（仅限完全隔离的可信网段） |

![设备页](/img/console/fleet.png)

<p class="shot-caption">两台网关，一台无认证（可信网段）、一台密钥认证</p>

:::note
网关行上的**最近可达**记录的是最近一次**成功同步**的时间，不是心跳。
判断机床当前是否在被正常备份，要看机台行的**最近校验**——那是[滚动镜像](/guide/mirror/)持续更新的。
:::

:::note
网关凭据以加密形式存储，不会在任何界面或 API 响应中回显。
更换密钥时重新注册一台网关即可，旧的可以停用。
:::

## 第三步：同步机台 {#sync}

点这台网关的**同步机台**。DNC Pro 会读取网关的机床配置，把台账填进来：

- **新增**：网关上有、DNC Pro 里没有的机床
- **更新**：名称、系统、型号、IP、编码、文件根目录等发生变化的
- **孤立**：曾经同步过、但这次网关配置里不见了的机床——
  **保留历史，不再对它执行任何操作**

同步是幂等的，可以随时重跑。机床增减、改名之后重跑一次即可。

## 第四步：划分机组 {#groups}

机组（Machine Group）是**授权和策略的单位**，不是位置的单位。它决定两件事：

1. **谁能操作这些机床**——[权限](/reference/rbac/)可以按机组授予
2. **这些机床允不允许试切**——机组级开关

演示环境的划分方式：

| 机组 | 机床 | 允许试切 |
| --- | --- | :---: |
| 加工中心组 | 立加01/02、卧加01、高速铣01、五轴01、精雕01 | <span class="sup-y">✓</span> |
| 车削组 | 数车01、车铣复合01 | <span class="sup-y">✓</span> |
| 钻攻中心组 | 钻攻01、钻攻02 | <span class="sup-n">✗</span> |

钻攻中心是量产节拍机，不允许出现试切程序——这条策略由机组开关强制，
不依赖谁记得。

## 每台机床的两个开关 {#machine-options}

在设备页的机台表里按行设置：

| 选项 | 含义 |
| --- | --- |
| **机组** | 归属哪个机组（决定授权与试切策略） |
| **严格模式** | 在这台机床的列表里**高亮标记未受管文件**。仅提示，**从不阻断**任何操作 |

严格模式适合用在"这台机床上就不该有计划外程序"的场合——
标出来让人去看，而不是拦下来让人去猜。

## 验证接入是否成功 {#verify}

同步之后不做任何操作，等一两分钟再回到设备页：

- 每台机床的**最近校验**应从空白变为"刚刚"——说明[滚动镜像](/guide/mirror/)已经扫过一轮
- 点进任意一台机床，应能看到它上面已有的文件，全部标为**未受管**

![机台文件](/img/console/machine-detail.png)

<p class="shot-caption">刚接入时，机床上原有的文件都是「未受管」——已经被备份，但不受任何策略约束</p>

如果某台机床的"最近校验"一直不更新，行内会显示具体失败原因
（例如 `备份失败: Machine offline.`）。常见原因见[常见问题](/faq/#mirror-fails)。
